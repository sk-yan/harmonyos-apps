# 验证说明

本仓库分别记录各层验证。某一层通过，只支持该层实际检查的行为。

| 层次 | 检查内容 | 不能据此证明 |
| --- | --- | --- |
| 账务核心与存储模拟测试 | 金额、账单规则和存储故障处理流程 | 真实 HarmonyOS 文件系统行为 |
| TypeScript 与预览打包 | 浏览器预览和共享代码的类型、构建 | ArkTS 编译与原生界面可用 |
| 浏览器交互验收 | 预览页面中的输入、统计、编辑等交互 | 手机或模拟器上的 ArkUI 行为 |
| 原生构建 | DevEco 工具链成功生成本次源码的 HAP | 包已签名、设备安装或功能正确 |
| 鸿蒙模拟器验收 | 指定镜像和设备模板上的安装与交互 | 所有机型兼容或真机可安装 |
| 真机验收 | 指定机型、系统与签名下的实际运行 | 所有用户、所有系统版本均可安装 |
| 应用市场发布 | 审核和上架状态 | 未测试功能或其他渠道的安装情况 |

## 如何记录后续结果

Release 记录应用版本、源码提交、执行命令、实际结果及检查日期。设备测试还需列出系统/API 版本、机型或模板、折叠状态和验收范围。失败或跳过的项保留原因，不用已有旧版本结果填补。

持续集成的通过标识只表示对应工作流通过。当前根目录的前端检查不包含原生 SDK、模拟器、真机或签名验证；浏览器交互验收也应单独注明是否实际执行。

原生交互测试应在可清理的专用测试模拟器上运行，使用测试账单，避免对日常账本执行新增、编辑和删除。公开仓库只保留脱敏后的说明和截图，不提交含本机账号、路径、设备标识或个人账目的原始日志。
