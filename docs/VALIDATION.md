# 验证说明

本仓库分别记录各层验证。某一层通过，只支持该层实际检查的行为。

| 层次 | 检查内容 | 不能据此证明 |
| --- | --- | --- |
| 账务核心与存储模拟测试 | 金额、账单规则和存储故障处理流程 | 真实 HarmonyOS 文件系统行为 |
| TypeScript 与预览打包 | 浏览器预览和共享代码的类型、构建 | ArkTS 编译与原生界面可用 |
| 浏览器交互验收 | 预览页面中的输入、统计、编辑等交互 | 手机或模拟器上的 ArkUI 行为 |
| 文件与图片解析测试 | 合成 CSV / XLSX、状态判定、OCR 文字草稿与边界条件 | 所有平台导出版本或真实图片均能正确识别 |
| 浏览器真实 OCR | 当前浏览器对实际测试图片的识别及人工核对流程 | 原生 Core Vision OCR 可用 |
| 原生构建 | DevEco 工具链成功生成本次源码的 HAP | 包已签名、设备安装或功能正确 |
| 鸿蒙模拟器验收 | 指定镜像和设备模板上的安装与交互 | 所有机型兼容或真机可安装 |
| 真机验收 | 指定机型、系统与签名下的实际运行 | 所有用户、所有系统版本均可安装 |
| 应用市场发布 | 审核和上架状态 | 未测试功能或其他渠道的安装情况 |

## 一笔记账 1.1.0-preview.2

当前共享核心、存储模拟与 XLSX 测试合计 58 项通过，TypeScript 检查通过。覆盖 5,000 行导入、超限拒绝、长交易单号、重复与疑似项、退款与状态变化、编辑后的身份保留、v1 旧账本兼容、前置原子校验、XLSX 压缩和 XML 边界，以及截图缺失或歧义字段留空。

浏览器新增交互验收 12 组通过，未记录运行时错误或非同源请求。真实 OCR 测试使用一张清晰的合成中文单笔交易截图，在阻止非同源请求时提取到金额 `38.50`、日期 `2026-09-10`、支出方向及测试商户文字；该单样例不支持对真实截图整体准确率作结论。

本次已完成原有原生功能 8 组回归，导入相关 8 项按文件平台 6 项与最终键盘/文字草稿 2 项分段通过；浏览器原有 9 组与新增 12 组串联通过。生产静态预览也实际通过 CSV 导入与本地中文 OCR。详见[本次记录](../apps/yibi-ledger/docs/verification-1.1-preview.2.json)及[改进记录](IMPROVEMENTS-1.1.md)。

原生图片识别依赖系统 Core Vision OCR，官方不支持模拟器；因此模拟器上的粘贴文字、草稿核对和保存验收不能证明真实手机图片 OCR 已通过。Mate X6 已完成本地签名安装、外屏账单重点流程及系统图片 OCR 验证；物理内屏旋转和大字体组合未覆盖。

## 如何记录后续结果

Release 记录应用版本、源码提交、执行命令、实际结果及检查日期。设备测试还需列出系统/API 版本、机型或模板、折叠状态和验收范围。失败或跳过的项保留原因，不用已有旧版本结果填补。

持续集成的通过标识只表示对应工作流通过。当前根目录的前端检查不包含原生 SDK、模拟器、真机或签名验证；浏览器交互验收也应单独注明是否实际执行。

原生交互测试应在可清理的专用测试模拟器上运行，使用测试账单，避免对日常账本执行新增、编辑和删除。公开仓库只保留脱敏后的说明和截图，不提交含本机账号、路径、设备标识或个人账目的原始日志。
